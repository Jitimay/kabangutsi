### OCR — PaddleOCR (heavy CPU run, done 2026-10-31 ~13:45–14:00)
Models: `PP-OCRv5_mobile_det` (4.8 MB) + `latin_PP-OCRv5_mobile_rec` (8.0 MB, covers French/English/Kirundi Latin script).

Caveat: synthetic printed text is easy. Real phone photos and **handwritten** loan forms will score lower; need a real
(fictional-content) photo test in Wave 6.

Findings that matter for the Dockerfile (Wave 6):
- **Pin `paddlepaddle==3.2.2`.** 3.3.1 crashes on CPU: `NotImplementedError: ConvertPirAttribute2RuntimeAttribute not support`
  (oneDNN). `enable_mkldnn=False` avoids it but is **~5× slower** (5.5–7.5 s/image).
- PaddleOCR downloads models on first `PaddleOCR()` into `~/.paddlex/official_models/` and pings model hosts.
  Prevent at runtime: download at build time, pass `text_detection_model_dir` / `text_recognition_model_dir`,
  set `PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK=True`. Verified: runs inside a network-less namespace.
- When model dirs are given, `lang=` is ignored: name the models explicitly (`text_*_model_name`).
- paddlex pulls `opencv-contrib-python` (non-headless) → image needs `libgl1` + `libglib2.0-0`.
- Pinned versions: `ocr/experiments/requirements.txt`.

### PDF — WeasyPrint 70.0
`pdf_test.py` renders a fictional loan simulation (5 000 000 FBu, 24 months, placeholder rate) in fr, en, rn.
0.07–0.12 s per PDF, A4, ~8–9 KB, one page. Run with networking disabled: OK.
- WeasyPrint 70 removed `default_url_fetcher`; use `URLFetcher(allowed_protocols={"file", "data"})` to forbid http(s).
- Fonts must be bundled (`@font-face` with a `file://` URL). Page margin boxes (page numbers) don't inherit
  `body` font: set `font-family` in `@page` too, or a system font sneaks in (seen: Nimbus-Roman).
- Number formatting in the test uses `5,000,000`; real templates should use the locale style (`5 000 000 FBu`).
- Kirundi labels in the test template are a draft: **need review by a Kirundi speaker** before the real templates.

### SMS — GSM modem
- No USB GSM dongle was attached. The only device was a **Samsung Galaxy S10e (SM-G970F), Android 12, SIM operator LUMITEL**,
  exposing `/dev/ttyACM0`.
- Every AT command on `/dev/ttyACM0` returns `+CME Error:PACM(AP),NOT_ALLOWED_SLO` / `UNREGISTED` → Samsung blocks the
  modem port. **gammu/AT on this phone: not possible.**
- Plan: **SIM800A + Arduino Nano** (team hardware). Nano runs `sim800_passthrough.ino` (SoftwareSerial D10/D11, 9600 baud),
  host talks AT through the Nano's USB serial (`/dev/ttyUSB0` on CH340 clones). Test command:
  `python sms/experiments/at_probe.py /dev/ttyUSB0 --baud 9600` then `--send +257XXXXXXXX "test"` / `--list`.
  Notes: SIM800A is 2G only (GSM 900/1800); needs a 2 A supply (Nano 5 V pin is not enough); share GND.
  Docker: the device to pass in will be `/dev/ttyUSB0` (or `/dev/ttyACM*`), group `uucp` on this Arch host.
- Fallback if the SIM800A fails: the phone has the open-source app **SMS Gateway for Android** (`me.capcom.smsgateway` 1.58.0).
  Its Local Server API can be reached over USB with `adb forward` (no Wi-Fi, no internet):
  `sms/experiments/android_gateway_test.py`. Not run: its SMS permissions are currently auto-revoked by Android
  and Local Server is off.
