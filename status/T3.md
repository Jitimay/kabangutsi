## Step 1 results (CPU only, 4 threads, 2026-10-31)

**Measurement conditions:** the machine was shared with an Android Studio/Gradle build (T2) and other
sessions: load avg 1–6, only 1–3 GB RAM free, swap full. Latencies below are therefore **pessimistic**;
I will re-measure on an idle machine before the service is built.

**Test audio is synthetic** (no recordings available): TTS output, espeak-ng, and a "phone" copy
(8 kHz + noise, 20 dB SNR). Real callers will give higher WER. 10 banking sentences per language
(`voice/experiments/sentences.py`), ~2.6–3.2 s each.

"Latency per 5 s of audio" as asked: Whisper always encodes a padded 30 s window, so cost is almost
fixed per utterance; per-5 s numbers are in the JSON (`latency_per_5s_audio_s`) but per-utterance is the
meaningful figure. espeak-ng (robotic) French breaks Whisper (WER 0.56–0.93); real voices should not.

**Kirundi STT details.** The `run` adapter exists (`adapter.run.safetensors`, 8.8 MB). int8 RAM: 2.6 GB
(fp32 ≈ 4 GB, which swaps on this shared machine; bf16 was >20 CPU-min without finishing, unusable).
int8 costs ~3 WER points versus fp32. Word errors are mostly near-misses: character error rate is 13 %, e.g.
`amasaha` → `amasara`, `gitondo` → `gitono`, `kwugurura konti` → `kugururako`. That is fine for intent
keywords plus an LLM that tolerates spelling noise, but not for exact transcripts. It is also optimistic,
because the test audio is MMS-TTS speech (same project). The int8 model is built by
`voice/scripts/quantize_mms.py` (70 s, peak 6.3 GB RAM: run it at image build time, not at runtime).

### Gemma 4 audio (Ollama `gemma4:e4b`)
- `ollama show`: capabilities include **audio**. Audio is sent as base64 WAV in `images`.
- Works: correct fr and en transcripts + language tag. But **14.6 s warm** for a 3 s clip
  (cold load 112 s, ~7 GB RAM). Not usable for live STT; no gain over Whisper. Not tested on rn yet.

### Decisions / recommendations (for the inspector)
1. **fr/en STT:** faster-whisper int8 with a **language hint** from the session (skip auto-detect after the
   first turn: it doubles latency). `base` meets < 1 s even under load; `small` is clearly more accurate
   in French (5 % vs 13–20 % WER). → Step 2 decision: default `base` (see Step 2 results).
2. **rn STT:** Whisper cannot do Kirundi and never detects it → backend must route `rn` audio to MMS by
   session language (Whisper auto-detect would mislabel Kirundi as sw/fr). MMS int8 works: WER ~0.6 /
   CER 0.13, ~2.2 s per 3 s utterance (misses the 1 s target). Usable for intent detection with
   confirmation ("did you mean…?"), not for free dictation. Recommend: rn voice calls show the transcript
   on screen + pre-recorded phrases; re-test with real Kirundi recordings.
3. **fr/en TTS:** Piper meets the < 0.7 s first-sentence target. Default voices: siwis (fr), lessac (en).
4. **rn TTS:** works but ~1.5 s per sentence → split replies into short clauses + pre-generated phrase
   cache. Fallback (text on screen + pre-recorded phrases) only if the native-speaker score is < 3/5.
5. Gemma 4 audio: not used for STT.

## Step 2 results — voice service (HTTP, warm, 2026-11-02, quiet machine)

Defaults: fr/en STT **faster-whisper `base`** int8, rn STT MMS-1b-all+run int8, TTS Piper siwis/lessac, MMS-TTS rn.
RAM: **4.2 GB** for everything. Startup: ~20 s (models ~12 s + phrase cache 8 s).

| Endpoint | fr | en | rn | Target |
|---|---|---|---|---|
| `/stt` with `lang` hint (≈3 s clip) | **0.78 s** | **0.79 s** | 1.12 s | < 1 s per 5 s audio |
| `/stt` auto-detect | 1.45 s | 1.33 s | 1.94 s (max 3.9) | — |
| `/tts` one sentence | **0.23 s** | **0.23 s** | 0.64 s | < 0.7 s |
| `/tts` phrase cache hit | 2 ms | 2 ms | 2 ms | instant |

**Change from Step 1:** default Whisper is now `base`, not `small`. On this shared machine `small` takes
3–7 s per sentence when other terminals are busy (measured back-to-back: base 1.0–2.0 s, small 3.0–7.4 s),
which breaks the 3 s turn budget. Cost: French WER 13–20 % instead of 5 % (synthetic audio). If the demo
machine is otherwise idle, `VOICE_WHISPER_SIZE=small` switches back.

**Auto-detect (no `lang`):** `base` alone misroutes 2 of 100 test clips (one fr → rn, one rn → fr, both in
the P(fr)+P(en) 0.3–0.7 band). In that band `small` is loaded as a language-ID referee only (one extra
encoder pass, ~+0.5 GB RAM) → all test clips routed correctly. Auto-detect still costs ~+0.6 s, so the
backend should send `lang` whenever the session language is known.

**Kirundi int8 build:** the old quantiser kept every layer's fp32 copy alive (6.3 GB peak, OOM-killed once);
fixed + the weights are now streamed tensor by tensor from the mmap'd file.
